# Komari 中国方向延迟告警插件

当 Komari Agent 保持在线，但连续无法获取多个中国大陆延迟目标的 ICMP 结果时，通过插件独立配置的 Telegram Bot 发送异常和恢复通知。

## 判断规则

默认每 60 秒检查一次，可在管理页面调整为 30～3600 秒：

- Agent 必须在线；
- 选择的国内延迟任务中至少 5 个失败或数据过期；
- 连续异常 3 次后告警；
- 连续恢复 2 次后发送恢复通知；
- 同一轮异常只告警一次；Telegram 发送失败会在后续检测中重试。
- 未分配给某台服务器的延迟任务不会参与该服务器判断；实际可用目标少于阈值时显示“目标不足”，不会误报。

## Telegram 命令

插件每 10 秒通过 Telegram `getUpdates` 检查一次消息，只接受配置的 Chat ID；配置 Topic ID 后，还会限制为该话题。

- `/check`：先回复正在检查，再检测全部已选择服务器，并按管理页面保存的顺序返回与 `/status` 相同的完整节点列表；本轮不重复发送单独的异常或恢复通知；
- `/status`：查看最近一次检测结果；
- `/alerts`：只查看异常告警和等待确认的服务器；
- `/help` 或 `/start`：查看帮助。

同一个机器人不能同时使用 Telegram Webhook 和 `getUpdates`。建议为本插件创建专用机器人；如果机器人已配置 Webhook，管理页面会显示轮询冲突错误。

保存 Telegram 设置时，插件会通过 `setMyCommands` 注册命令，并通过 `setChatMenuButton` 将私聊菜单按钮设置为命令列表。也可以在管理页面点击“同步菜单”手动重试。

这里的“异常”表示服务器与多个中国大陆目标之间的 ICMP 往返通信异常，可能由 IP 屏蔽、机房中国方向路由故障、运营商故障或 ICMP 策略引起，不能单独证明 GFW 封锁。

## 安装

1. 使用版本化安装包 `komari-gfw-monitor-v0.3.9.zip`。
2. 进入 Komari 管理后台的“插件”页面并上传 ZIP。
3. 启用插件并批准 `allowSystemRPC` 和 `allowRoutes` 权限。
4. 打开“中国方向告警”插件页面。
5. 填入 Telegram Bot Token、Chat ID，选择服务器和国内延迟任务。
6. 先点击“发送测试”，确认 Telegram 能收到消息。
7. 保存设置并启用监控。

插件要求 Komari `1.5.1` 或更高版本。

## Telegram 配置

- 使用 `@BotFather` 创建 Bot 并取得 Bot Token。
- 先给 Bot 发送一条消息，或将 Bot 加入目标群组。
- 私聊 Chat ID 通常是正整数，群组或频道通常以 `-100` 开头。
- 如果发送到开启话题的群组，可填写 Topic ID。

Bot Token 存储在 Komari 的 `data/plugin-data/gfw-monitor/config.json` 中。请保护 Komari 数据目录，不要将该文件提交到 Git。

## 变更记录

### v0.3.9

- Telegram 收到 `/check` 后恢复发送“正在检查所有已配置服务器”的进度提示；
- 检测完成后继续发送与 `/status` 相同的完整排序列表。

### v0.3.8

- Telegram `/check` 完成后使用与 `/status` 完全相同的“当前状态”列表格式；
- 即使全部节点正常，也逐行显示所有节点，不再折叠为单行结果；
- 节点序号、状态、失败目标数、保存顺序和检测时间均保留。

### v0.3.7

- 当前状态表支持拖动节点手动排序，排序保存在插件配置中；
- 定时检测、正式异常与恢复通知、`/status`、`/alerts` 均遵循保存的节点顺序；
- Telegram 异常与恢复通知改为精简格式；
- `/status` 和 `/alerts` 改为每台节点一行的紧凑列表；
- Telegram `/check` 不再预先发送“正在检查”，完成后只发送一条排序后的精简汇总；
- `/check` 触发的异常或恢复合并进汇总，不再重复发送单独通知。

### v0.3.6

- 保存设置时自动清除已经取消监控的服务器状态，不保留无效状态记录；
- 状态页按目标显示“无记录、数据过期、Ping 失败、查询错误”等详细失败原因；
- 状态页和 Telegram 状态增加最后正常时间与异常持续时间；
- Telegram 新增 `/alerts`，只显示异常告警和等待确认的服务器；
- 异常通知增加失败原因汇总，便于快速判断问题类型。

### v0.3.5

- Telegram `/status` 将异常告警和等待确认的服务器排在正常服务器前面；
- 使用独立活动告警状态跟踪恢复，Agent 短暂离线后恢复也不会漏发恢复通知；
- 活动告警期间不重复发送异常通知，连续恢复达到阈值后发送恢复正常通知。

### v0.3.4

- 当前状态表增加每台服务器的“单独测试”按钮；
- 单独测试只查询指定服务器的国内延迟结果，减少不必要的批量查询；
- 单独测试按照现有规则累计一次连续异常并更新该行状态。
- 修复管理页面操作失败时不显示错误信息的问题。

### v0.3.3

- 服务器列表增加“全选结果”和“取消选择”；
- 有搜索条件时只操作当前匹配结果，没有搜索条件时操作全部服务器。

### v0.3.2

- 服务器搜索支持名称、UUID、标签、分组、IPv4 和 IPv6；
- 服务器列表直接显示节点标签、分组和 IP 地址；
- 兼容分号或逗号分隔的标签字符串，以及数组和对象格式。

### v0.3.1
